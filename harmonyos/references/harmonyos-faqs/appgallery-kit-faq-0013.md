**Q：同一个应用如何上架分发到手机、PC、平板多端设备，工程代码和HarmonyOS 开发者中心侧如何配置？**

**A**：应用上架时，需根据软件包中声明的设备（即module.json5配置文件中"[deviceTypes](../harmonyos-guides/module-configuration-file.md#devicetypes标签)"标签的枚举值）勾选对应的支持设备，确保软件包中声明的设备范围大于等于HarmonyOS 开发者中心上勾选的支持设备范围。提交审核时会进行校验，如果HarmonyOS 开发者中心上勾选的支持设备范围大于软件包内声明时，会提示上传的软件包与声明支持设备不一致，将无法提交审核。

**Q：HarmonyOS 开发者中心应用信息中的支持设备勾选分发的规则有哪些需要注意？**

**A**：规则如下：

1、当设备类型包含手机时，即便包里未声明平板，应用也会默认以兼容的方式分发到HarmonyOS NEXT平板。

2、当设备类型未勾选PC/2in1时，但手机和平板应用经过测试后会默认发布到PC/2in1。

更多详情参考[配置支持设备](../app/agc-help-release-app-devicetype-0000002271592112.md)。

**Q：应用在手机端已上架，PC端和平板与手机端功能有所不同，如何只针对PC端和平板上架？**

**A**：需要重新创建项目单独上架PC端和平板，包名和手机端区分开。

**Q：已上架应用仅支持手机/平板，想新增支持PC，除修改module.json5中的deviceTypes配置项外还需做哪些改动？**

**A**：仅修改deviceTypes只是声明该HAP可在PC（2in1）上安装/运行，并不代表已完成PC适配。配置可写为：

```json
"deviceTypes": ["phone", "tablet", "2in1"]
```

还建议逐项检查以下内容：

1. 所有会随应用交付的Entry/Feature HAP都要确认module.deviceTypes包含2in1。
2. 做系统能力与API兼容性检查。PC有独立的系统能力集合，手机/平板可用的API、权限或硬件能力不一定都可用，需要为不支持项提供判断、降级或替代实现。
3. 完成大屏和自由窗口适配：窗口拉伸、最大化/最小化、横屏、不同宽高与缩放比例下不应出现固定尺寸、遮挡或留白问题。
4. 补齐PC输入方式：鼠标悬停/右键/滚轮、触控板、键盘焦点与Tab顺序、快捷键、拖拽等。
5. 检查多窗口及窗口尺寸变化时的状态保存、页面恢复和生命周期逻辑。
6. 使用PC模拟器和真机完整回归；发布侧提交新版本，并确认分发设备类型、PC截图/素材和审核信息已补齐。

如果现有工程本身已经采用响应式布局，所用能力也都支持PC，业务代码未必必须改；但deviceTypes只是最小配置改动，仍需通过上述适配和测试后再新增PC分发。

**Q：应用提交审核时提示检测到当前软件包的user\_grant类型权限与隐私声明不一致，请修改后重新提交，应如何排查？**

**A**：请参考下述步骤进行排查。

1. 查看项目module.json5文件的requestPermissions标签，列出其中的隐私权限；
2. 排查是否使用了已废弃权限，例如[ohos.permission.WRITE\_MEDIA](../harmonyos-guides/permissions-for-all-user.md#ohospermissionwrite_media)权限。需要根据文档说明使用替换方案。
3. HarmonyOS 开发者中心平台上打开隐私协议，查看设备权限调用模块中包含的隐私协议，与步骤（1）结论对比，并修改一致；
4. 若问题没有解决，在HarmonyOS 开发者中心提交审核界面查看应用隐私说明模块列举的权限，与隐私协议中权限对比，并修改一致。（软件包存在部分权限通过其他包引入，没在module.json5文件中声明，需要判断是否有必要引入该包。）
5. 检测是否使用了隐私协议服务，和配置的权限是否和软件包中一致。

补充说明，若隐私政策声明中设备权限调用展开为空，通常是因为软件包中声明了user\_grant权限但隐私声明中未同步声明。建议按以下方向处理：

* 若业务确实需要对应权限（如读写日历），在发布侧隐私声明的设备权限调用中补充对应权限，并填写用途说明，用途应与module.json5中requestPermissions的reason保持一致。
* 若当前版本未实际使用该权限，从requestPermissions中移除对应权限，重新打包后再提交。
* 重新提交前，确认requestPermissions中的权限清单与隐私声明设备权限调用中的权限清单完全一致。
* 若在发布侧补充权限后设备权限调用仍为空，检查是否选择了正确的应用、包名和版本，或重新上传包后刷新隐私声明配置。

另外，针对常见的不一致场景，可按以下方式处理：

* 权限只在软件包中声明（如WRITE\_MEDIA）：优先从requestPermissions中删除。READ\_MEDIA/WRITE\_MEDIA从API Version 22起已废弃，保存/选择图片、视频、文件建议改用Picker、保存控件或新的媒体访问能力。
* 权限只在隐私政策中声明（如LOCATION\_IN\_BACKGROUND）：若应用没有后台定位功能，从隐私政策/HarmonyOS 开发者中心权限声明中删除；若确实需要后台定位，在module.json5中声明LOCATION\_IN\_BACKGROUND，同时补齐前台定位权限、权限申请原因、使用场景，并按后台定位要求申请定位类长时任务，参考[位置权限申请](../harmonyos-guides/location-permission-guidelines.md)。
* 检查所有模块：不只看entry，还要查feature/HSP/HAR、三方SDK等配置，确认最终打包产物里没有残留权限。
* 修改后clean/rebuild，重新上传包，并同步更新隐私政策权限清单。

**Q：APP备案时有一个"相关前置许可"是否的选项，应该怎么选，有涉及到前期准备材料和工作吗？**

**A**：APP仅提供普通工具、信息展示、企业官网配套等无专项许可要求的服务，无需前置许可。

APP业务涉及新闻、出版、教育、医疗、文化、视听、网约车、金融、宗教等国家规定需前置审批的行业，必须先取得对应许可并上传文件。如下表：

| 行业类别 | 必备许可文件 | 批复单位 |
| --- | --- | --- |
| 新闻类 | 《互联网新闻信息服务许可证》 | 各省网信办 |
| 出版/游戏 | 《网络出版服务许可证》、游戏版号 | 省级新闻出版部门 |
| 校外培训 | 教育部门培训审批文件 | 省市区教育行政部门 |
| 药品/医疗器械 | 《互联网药品信息服务资格证书》 | 省级药监局 |
| 文化类 | 《网络文化经营许可证》 | 各省文旅厅 |
| 视听节目 | 《信息网络传播视听节目许可证》 | 省级广电 / 宣传部门 |
| 网约车 | 《网络预约出租汽车经营许可证》 | 注册地交通委 |
| 金融类 | 金融监管部门审批文件 | 金融类 金融监管部门审批文件 央行、银保监会、证监会等 |
| 审教类 | 《互联网宗教信息服务许可证》 | 省级以上宗教事务部门 |

办理相关许可证：

1. 确认审批部门：根据上表找到对应的批复单位，联系当地主管部门咨询具体办理流程。
2. 准备申请材料：通常包括：营业执照、法人身份证明、业务说明、技术方案、场地证明等（各行业要求不同，需向主管部门确认）。
3. 提交申请并等待审批：审批周期一般为20-60个工作日（视行业和地区而定）。拿到许可证原件后，在备案系统中选择对应前置审批类型，填写审批号并上传扫描件。
4. 备案上传：在APP备案系统选择对应审批类型，填写审批号并上传许可文件。

可参考文档：[前置审批行业类别及批复单位](https://support.huaweicloud.com/prepare-icp/zh-cn_topic_0000002085124433.html)。

HarmonyOS应用备案的前期准备工作：

1. HarmonyOS特有信息：包名、公钥、MD5指纹（从开发者证书提取）。
2. 基础材料：准备法人身份证、营业执照原件扫描件、手持证件照片以及域名证书。
3. 服务商信息：确认你使用的接入服务商（如华为云、腾讯云等）的详细备案信息。

总结建议：如果APP是普通的商业应用或个人工具，且不属于上述限制性行业，请在"相关前置许可"项选"否"，即可正常推进备案流程。

**Q：提交审核时提示应用名称与最近任务列表的应用名称不一致，如何处理？**

A：该问题通常是因为工程中声明的设备类型与提交审核时勾选的设备类型不一致导致的。例如应用只适配了手机，但提交审核时勾选了PC和平板，导致提交审核的设备类型与工程中的设备类型不匹配。需要在工程的module.json5配置文件中增加对应的设备类型，确保工程中声明的设备范围与提交审核时设备范围一致。配置示例如下：

```json
"deviceTypes": ["phone", "tablet", "2in1"]
```

同时，请确保提交的应用名称、应用图标与应用安装后终端显示的应用名称、应用图标一致，可参考[《应用审核指南》](../app/50104-01.md)第1.20项。

**Q：HAR和HSP是否也会存在多设备品类强制审核的情况？例如HAP打包发布应用后，仅针对手机做版本更新，但强制要求手表也进行版本审核，有没有办法解决该问题？**

**A**：HAR和HSP均不能独立上架，上架审核的基本单元始终是App Pack（由HAP组成）。只要应用在应用市场已上架了手表品类，后续每次版本更新都会按已上架设备品类进入审核流程，换用HAR或HSP无法规避。目前可以采取以下两种方式提高效率：

1. 分两个应用上架，审核时任一端有问题不会影响整体上架流程，可以提高上架时效。
2. 如应用临时出现严重错误，需要紧急修复，可以申请加急审核。在互动中心详细描述需加急审核的原因，工作人员将尽快安排审核。
